# 前端设计规格

## 视觉来源

- `/chat` 桌面概念：`design/concepts/chat-desktop-v1.png`
- `/memories` 高保真概念：内置图片服务两次网络失败，待补。
- 已实现页面使用 Playwright 在 1600×1000 远端环境完成布局、交互和控制台检查；这证明
  当前 UI 可操作，但不替代缺失的 `/memories` 概念稿逐项视觉对照。

远端验收截图：

- `design/qa/remote-chat-1600x1000.png`

## 设计系统

- 背景：纯白；不替换为米白或灰白。
- 主文本：charcoal；辅助文本使用中性灰。
- 主色：cobalt blue；成功：restrained mint；等待/Speech Gate：amber；破坏操作：red。
- 间距：8px 基础尺度；主要 panel 使用开放分隔线，不使用嵌套卡片堆叠。
- 圆角：8-12px，仅用于输入、按钮、状态区域和必要容器。
- 字体：中文 UI 优先系统无衬线；所有表格、工具栏、字段标签显式定义字号与行高。

## App Shell

固定导航只有：

1. 实时对话
2. 记忆工作台
3. 实验评测
4. 系统状态

顶部上下文栏显示已验证能力、记忆空间和记忆实验条件。未接入的对话、TTS、
向量模型必须明确显示“未配置”，不得以可选模型或演示卡出现。空间切换必须
结束或显式迁移当前会话，禁止静默换空间。

## `/chat`

必须包含：

- 对话与音频播放；
- 按住说话、停止和打断；
- Speech Gate 状态；
- 延迟时间线与原始事件轨迹；
- 本轮 ReME、图谱、来源文件、Context Pack token 数；
- 召回/回答使用反馈；
- 点击打开原始 Markdown、图片与图谱路径。
- 公网 HTTP 下始终可上传 WAV/MP3/OGG Opus 合成音频完成 ASR，并显示转写和时长；
  麦克风仍受浏览器安全上下文限制。

概念中的 trace 数字只是合成展示数据，实现不得把它们当成实际测量结果。

## `/memories`

采用“库列表 + 编辑器 + 发布预览”三栏结构：

- 库列表使用表格/行，不改成卡片网格；
- 编辑器同时管理 frontmatter、Markdown、图片和版本；
- 发布预览显示 ReME 摘要、实体/关系/事件/冲突候选及每条来源；
- 人工确认后才能发布；
- 操作明确区分保存草稿、提交审核、确认发布、撤回、移入回收站、恢复和永久删除；
- 清理中心独立为 drawer/page，不把高风险操作常驻在主编辑区。

## 响应式边界

- 首要验收尺寸：1600×1000 与 1440×900；
- 1024px 以下把右侧证据/发布预览变成 drawer；
- 移动端只支持查看、录音/打断和轻量反馈，不支持复杂 Markdown/图谱编辑；
- 不允许主操作、波形、发布状态或 memory space 在折叠时消失。

## 交互验收

- `/chat`：选择空间 -> 建会话 -> 录音 -> 查看 Gate/轨迹 -> 打断 -> 反馈；
- `/memories`：上传 -> 编辑 -> 提交审核 -> 修改候选 -> 发布 -> 对话召回 -> 撤回；
- 草稿和撤回内容在 `/chat` 搜索结果中必须为 0；
- 所有高风险清理操作显示具体空间、对象计数和二次确认文本。
